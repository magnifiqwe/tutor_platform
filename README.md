# Практика — платформа Валерия

Версия 0.1.0. Самостоятельный full-stack проект для одного репетитора и его учеников. Русский интерфейс. Название «Практика» рабочее, меняется в `src/main.tsx` и `index.html`.

> [!important] Статус
> Исходники созданы, TypeScript и production-сборка проверяются, есть автоматические проверки API, доступа, WebSocket, списаний и настоящего Python через Pyodide. Проект **ещё не развёрнут на вашем VPS**. Сквозная проверка в двух настоящих браузерах, внешний HTTPS, iframe/SAB и нагрузка 3–5 пользователей в этой среде не выполнены. Перед первым реальным уроком пройдите `docs/ACCEPTANCE.md`.

## Реализовано

- Закрытые аккаунты: преподаватель создаёт учеников, меняет пароль, блокирует доступ. Самостоятельной регистрации и родительского кабинета нет.
- Обзор занятий и календарь по месяцам; создание, перенос, завершение и отмена занятий.
- Карточка CRM: контакт, заметки, этап обращения. Заметки доступны только преподавателю.
- Покупки с индивидуальной суммой, количеством и длительностью 60/90 минут. Разовая покупка — пакет из одного занятия.
- Привязка оплаты к будущему уроку, резервирование доступного занятия, однократное списание, бесплатный пробник. Ученик видит остаток и статус оплаты, но не цены.
- Постоянная Excalidraw-доска ученика с серверным сохранением и обменом изменениями. Вне открытого урока ученик только смотрит.
- Переключение между комнатами в одной вкладке. Уже открытые комнаты и исполнители остаются смонтированы при переключении.
- Python-проект на каждый урок, несколько файлов, совместный редактор CodeMirror + Yjs, курсоры участников.
- Файлы добавляет преподаватель. Код редактируют оба в открытом уроке. После закрытия доступны просмотр и скачивание.
- Python запускает преподаватель; `input()` вводит преподаватель; консоль и Turtle транслируются ученику. Есть остановка и лимит запуска 120 секунд.
- Учебные файлы читаются и изменяются программой, результаты успешного окончания/ошибки исполнения сохраняются на сервере. Принудительная остановка уничтожает worker, поэтому изменения файлов незавершённого запуска теряются.
- Markdown: заголовки, выделения, списки, таблицы, код, цитаты и картинки; обычные ссылки и Obsidian `![[изображение.png]]`. Загрузка `.md` и картинок отдельными файлами.
- Домашка привязана к уроку: текст/ссылка → попытки решения → оценка 1–5 и комментарий → при необходимости доработка. Фотографии, таблицы и файлы решений передаются ссылками на внешний диск.

## Локальный запуск

Нужен Node.js 24 и npm. Зависимости зафиксированы в `package-lock.json`.

```bash
npm ci
npm run check
npm test
npm run build
```

Создать преподавателя в Bash, не записывая пароль в историю команд:

```bash
read -rp 'Логин преподавателя: ' ADMIN_LOGIN
read -rsp 'Пароль (от 12 символов): ' ADMIN_PASSWORD
export ADMIN_LOGIN ADMIN_PASSWORD
npm run admin
unset ADMIN_LOGIN ADMIN_PASSWORD
npm start
```

Открыть `http://localhost:3000`. Python работает на отдельном `http://localhost:3001`. Используйте именно `localhost`, а не IP: в обычном HTTP по внешнему IP SharedArrayBuffer недоступен. `localhost` считается доверенным контекстом браузера.

Данные сохраняются в `data/platform.sqlite`. После перезапуска они остаются. Пример урока и Python находятся в `examples/`. Демонстрационные ученики или пароли в проект не добавлены.

`npm run dev` перезапускает сервер при изменениях; интерфейс при этом нужно пересобирать через `npm run build`.

## Развёртывание на VPS

Хостинг не привязан к Cloudflare, Google или иностранному CDN. Node, зависимости и Docker-образы загружаются при установке; во время уроков frontend, шрифты Excalidraw и Python/WASM отдаются с вашего сервера. Общую доступность по всей России нужно проверить с реальных сетей учеников.

1. Установить Docker Engine и Compose на VPS.
2. Создать две DNS A-записи на IP VPS, например `study.example.ru` и `python.example.ru`. Для них использовать обычный DNS без проксирования CDN. Второй адрес нужен для изоляции Python от авторизованного приложения.
3. Открыть TCP 80/443. Скопировать проект на VPS.
4. Настроить домены и запустить:

```bash
cp .env.example .env
# Отредактировать APP_DOMAIN и RUNTIME_DOMAIN в .env

docker compose up -d --build
```

Caddy получает TLS-сертификаты для обоих доменов автоматически. Порты приложения 3000/3001 наружу не публикуются.

Создать преподавателя:

```bash
read -rp 'Логин преподавателя: ' ADMIN_LOGIN
read -rsp 'Пароль (от 12 символов): ' ADMIN_PASSWORD
export ADMIN_LOGIN ADMIN_PASSWORD
docker compose exec -e ADMIN_LOGIN -e ADMIN_PASSWORD app npm run admin
unset ADMIN_LOGIN ADMIN_PASSWORD
```

Открыть `https://study.example.ru`. Перед передачей ученикам выполнить проверку из `docs/ACCEPTANCE.md`. DNS, VPS и домен не создаются этими исходниками.

Логи:

```bash
docker compose logs --tail=100 app
docker compose logs --tail=100 caddy
```

## Поведение оплаты

1. Записать покупку: ученик, количество, длительность, фактически полученная сумма.
2. При создании урока выбрать пакет. Для пакета резервируется одно занятие и показывается «Оплачено».
3. После урока выбрать «Завершить и списать» и оставить отметку списания.
4. Завершение уменьшает баланс ровно один раз. Повторный запрос отклоняется.
5. Поздняя отмена имеет отдельный статус; решение о списании принимает преподаватель. В календаре показан срок отмены за 2 часа, автоматики списания по таймеру нет.
6. При отмене без списания резерв освобождается. У бесплатного пробника списания нет.

Покупки хранятся как неизменяемые записи. Изменение цены новой покупки не меняет старые. Возврат, исправление ошибочного списания и редактирование покупки через интерфейс в этой версии не реализованы. Урок без выбранного пакета можно завершить без списания; учёта долгов пока нет. При смене длительности создайте соответствующий пакет. Общий баланс суммирует занятия; разбивка по пакетам видна преподавателю.

## Python и Turtle

Python выполняется в Web Worker на **отдельном origin**. Это реальный CPython/WASM из Pyodide, а не разбор нескольких команд JavaScript. Общее редактирование и сохранение обеспечиваются сервером, запуск происходит только в браузере преподавателя. Закрытие браузерной вкладки прекращает запуск; сессия урока остаётся открытой, пока преподаватель её не закроет.

Доступны обычные алгоритмические модули (`math`, `itertools`, `collections`, `functools`, `re`, `csv`, `random` и др.), `input()`, чтение/запись файлов. **Pyodide не является полной настольной ОС:** произвольные процессы, tkinter, системные сокеты и часть платформенных модулей не поддерживаются. Установки сторонних Python-пакетов нет. Внешние сетевые запросы runtime ограничены CSP (`connect-src 'self'`). Runtime не получает cookie приложения и не содержит административного API; сервер приложения отклоняет изменяющие запросы с другого origin.

Turtle — собственный Canvas-адаптер для учебных задач, а не Tkinter. Поддерживаются:

- `Turtle()`, `forward/fd`, `backward/bk/back`, `left/lt`, `right/rt`;
- `goto/setpos/setposition`, `setx`, `sety`, `home`, `setheading/seth`, `heading`, `position/pos`, `xcor`, `ycor`;
- `penup/pu/up`, `pendown/pd/down`, `isdown`, `pencolor`, `fillcolor`, `color`, `pensize/width`;
- `dot`, `circle`, `begin_fill`, `end_fill`, `write`, `clear`, `reset`, `colormode`;
- `Screen().bgcolor`, `setworldcoordinates`;
- `speed`, `tracer`, `update`, `done`, `mainloop`, `exitonclick`, `hideturtle`, `showturtle`, `shape`, `setup`, `title` принимаются, но анимация, окно, курсор-черепаха и GUI-события не реализованы.

Отрисовка `circle` полигональная. `clear` очищает общий холст, не только конкретную черепаху. Цвет одним именем или RGB; отдельные разные цвета пера и заливки задаются через `pencolor` / `fillcolor`. Имя `turtle.py` зарезервировано адаптером. Файлы проекта находятся в одном каталоге: вложенные папки пока не поддерживаются.

Ограничения первой версии: один файл загрузки до 4 МБ, JSON-запрос до 12 МБ, возвращаемые файлы Python суммарно до 8 МБ, консоль до 1000 событий, Turtle до 20 000 команд. Не использовать для тяжёлых расчётов и больших наборов данных без расширения лимитов.

## Архитектура

| Слой | Реализация |
| --- | --- |
| Интерфейс | React, Vite, TypeScript, русский UI |
| API и авторизация | Express, HttpOnly/SameSite cookie, scrypt, проверка Origin |
| Реальное время | Socket.IO; Yjs + y-codemirror для текста; слияние версий элементов Excalidraw |
| Хранение | SQLite/WAL; ученики, покупки, уроки, материалы, доски, файлы и Yjs-документы |
| Python | Pyodide, отдельный origin, iframe + Web Worker, SharedArrayBuffer для input |
| TLS | Caddy |
| Развёртывание | Docker Compose, постоянный volume |

Один процесс сервера рассчитан на исходный небольшой онлайн. Горизонтальное масштабирование, несколько экземпляров сервера и полноценная история версий доски не реализованы. Доска использует версионирование элементов; сложные одновременные перестановки слоёв требуют отдельного тестирования. Размеры базы, браузерная память и нагрузка не профилировались.

## Резервные копии

Согласованный snapshot SQLite можно создать на работающем приложении:

```bash
docker compose exec app node scripts/backup.mjs
```

Путь будет напечатан, например `/app/data/backups/platform-...sqlite`. Скопировать файл вне VPS:

```bash
docker compose cp app:/app/data/backups/ИМЯ.sqlite ./ИМЯ.sqlite
```

В базе есть учебные материалы, аккаунты и хеши паролей, поэтому храните копии приватно. Для восстановления остановить приложение, заменить `platform.sqlite` в volume, убрать старые `platform.sqlite-wal` и `platform.sqlite-shm` при остановленном процессе, затем запустить приложение. Перед восстановлением сохранить текущую базу отдельно. Команда `docker compose down -v` удаляет постоянные данные — для обычной остановки используйте `docker compose down`.
